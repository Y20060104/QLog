# SISO 通知与十进制转换的定向对齐（2026-10-16）

本轮根据用户授权，先验证复制/hash 融合，再定位普通接口批次延迟，最后对齐十进制转换并复测。工作区起点为 QLog `feat/spsc-ring-opt@f643d62fa736ccb3dcda22f7d5c9a163d0014ccc` 加已有未提交修改；已备份并保留原 CR。固定生产参考整体仍为 BQLog `78cbfbef`，本次两个函数族明确采用参测的新参考 `086f2fd831af86fcfa40e90015f89626d498d3d7`。

## 决定

1. `siso_ring_buffer::alloc_write_chunk` 的低空间提示采用新参考规则：仅当前分配跨过半满边界时置候选提示，再 acquire 加载已发布的读游标，重新确认占用。该标志是唤醒提示；不表示实时队列是否为空。原分配、提交、回绕、数据布局、原子存放、恢复及 Debug 结构继续保持现有实现，不借此宣布 SISO 全面迁齐。
2. Layout 普通十进制整数统一调用新参考 `digit_pairs` / `write_decimal_digits`，两位查表并写入最终位置。覆盖原来未进入三位表的小计数器；有符号最小值通过无符号求幅值处理。其他进制、科学计数、符号、宽度与填充继续复用现有流程。
3. 原 `kDigits3` 仍供时间前缀的三位毫秒使用，保留该用途和所有 CR；只替换整数路径，不改前缀合同。
4. 新参考普通接口 HP 内联快路径、块内线程信息复用、合并等级/堆栈过滤、FAST 元数据和新的 Record 读取链继续作为独立迁移项。本轮不把几十纳秒残余差距自动分摊给其中某一项。
5. 性能探针仅存在于仓库外诊断副本；正式库不增加计数器、每条计时或替身。新增 `benchmark/diagnostics` 提供复制/hash、Vernam、SISO、离线 Layout 和普通接口间歇/连续负载工具，不进入默认主库构建。
6. 官方运行器新增默认关闭的 `--cleanup-output`：先记录输出文件 SHA-256 与原始测量，再校验绝对路径并只清理该进程自己的输出目录。官方负载、默认 HP 阈值、计时与 FAST 单列规则不变。

## 依据与验证

原批次测试在本机复现融合前约 1183、融合后约 1152、BQLog 约 57 ns/条；去掉组间间隔后 QLog P50 约 90 ns/条。计数副本预热后全部 HP，无 LP、无重试、无新 HP 分配；约一半记录持续报告低空间，超过一半批次真实通知。单独迁入新参考提示规则的未插桩副本，把原批次 P50 降至约 108 ns/条。新回归在原库上先失败，再在修改后通过。

十进制独立 A/B 的相同记录输出一致：计数器 Layout 五轮中位约 236→94 ns/条，四参数约 370→209 ns/条。纯 Layout CPU 采样中，有符号整数函数自身样本占比约 49.6%→9.9%；该占比不是整套 logger 的时间分摊。

实际 GNU、原生 MSVC Debug/Release 完整回归各 44/44，包括独立 `to_chars` 期望值、10 的幂邻域、2048 组随机值、UTF-8/UTF-16、符号与填充，以及 SISO 半满、及时消费、回绕与顺序回归。正式复测、参数、各轮结果和源码保护证据见 [性能定位报告](../validation/PERFORMANCE_INVESTIGATION_20261016_CHS.md)。

加密实现本轮不改。Vernam 使用固定输入与逐字节 XOR 期望值对照，并独立测量不同块长；算法对齐不保证机器码、代码布局和整条异步流水线耗时相同。加密场景的总吞吐不能自动归因于 RSA 或 Vernam 核心。
